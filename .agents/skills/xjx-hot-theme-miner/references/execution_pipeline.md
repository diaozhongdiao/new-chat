# 执行流水线与输出规范

## 概述

定义热门题材挖掘的完整执行步骤、各步骤间的数据流转关系，以及最终报告的输出格式规范。

---

## 执行流水线

```
Step 1: 市场情绪采集
   │
   ├── 获取涨跌停统计数据（参见 data_sources.md 第 5 节）
   ├── 计算市场情绪评级
   └── 输出: 上涨家数、下跌家数、涨停数、情绪评级
   │
Step 2: 题材数据采集
   │
   ├── 获取概念板块行情列表（参见 data_sources.md 第 1 节）
   ├── 获取涨停股列表及涨停原因（参见 data_sources.md 第 2 节）
   ├── 将涨停股按原因标签匹配到各板块
   └── 输出: 每个板块的涨幅、成交额、换手率、涨跌家数、涨停家数
   │
Step 3: 题材评分与 Top3 筛选
   │
   ├── 对每个板块执行三维评分（参见 theme_scoring.md）
   ├── 判定生命周期阶段和题材级别
   ├── 按综合得分降序排序，取 Top3
   └── 输出: Top3 题材（含得分、驱动逻辑、操作策略）
   │
Step 4: 成分股数据采集
   │
   ├── 获取 Top3 题材的成分股列表（参见 data_sources.md 第 1 节）
   ├── 对每个题材取涨幅前 10-15 只候选股
   ├── 查询候选股资金流向（参见 data_sources.md 第 3 节）
   ├── 查询候选股基本面数据（参见 data_sources.md 第 4 节）
   └── 输出: 候选股完整数据集
   │
Step 5: 个股评分与 Top5 筛选
   │
   ├── 对候选股执行五维评分（参见 stock_scoring.md）
   ├── 全部候选股按综合得分降序排序，取 Top5
   ├── 标注龙头地位、技术形态、资金趋势
   └── 输出: Top5 个股（含五维得分及详细数据）
   │
Step 6: 价格预测与策略生成
   │
   ├── 对 Top5 个股计算中长期目标价（参见 price_prediction.md）
   ├── 生成三情景预测（乐观/中性/悲观）
   ├── 计算预测置信度
   ├── 生成操作策略（仓位、入场、止损、出场）
   ├── 生成风险提示
   └── 输出: 完整预测与策略
   │
Step 7: 报告组装
   │
   ├── 组装市场情绪模块
   ├── 组装 Top3 题材模块
   ├── 组装 Top5 个股模块（含预测与策略）
   ├── 组装风险提示模块
   ├── 添加免责声明
   └── 输出: 完整 Markdown 报告
```

---

## 市场情绪评级标准

| 评级 | 条件 |
|:---|:---|
| **高潮** | 涨停数 ≥ 80 且 上涨家数/下跌家数 ≥ 3 |
| **活跃** | 涨停数 ≥ 40 且 上涨家数 > 下跌家数 |
| **中性** | 上涨家数 与 下跌家数 相差不大（0.8-1.2 倍） |
| **低迷** | 下跌家数 > 上涨家数 且 涨停数 < 20 |
| **冰点** | 涨停数 < 10 且 下跌家数/上涨家数 ≥ 3 |

## 数据流转约束

### 请求频率控制

为避免触发东方财富接口的访问限制，各步骤的数据请求需遵循以下规范：

| 操作 | 约束 |
|:---|:---|
| 概念板块列表 | 单次请求，获取全部板块 |
| 涨停股列表 | 单次请求 |
| 板块成分股 | 每个 Top3 板块请求一次（共 3 次） |
| 个股资金流向 | 每只候选股请求一次，建议每次请求间隔 0.3-0.5 秒 |
| 个股基本面 | 每只候选股请求一次，建议每次请求间隔 0.3-0.5 秒 |

### 数据缺失处理

| 缺失数据 | 处理方式 |
|:---|:---|
| 板块行情数据获取失败 | 报告错误，终止流程 |
| 涨停股列表获取失败 | 所有板块涨停数按 0 处理，继续评分 |
| 个股资金流向获取失败 | 资金面维度得分设为基础分，资金趋势标记为「数据不足」 |
| 个股基本面获取失败 | 基本面维度得分设为基础分，PE/营收/净利标记为「--」 |
| 价格数据缺失 | 跳过该个股价格预测，标注「数据不足」 |
